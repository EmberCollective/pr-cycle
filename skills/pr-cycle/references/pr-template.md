## 一句话变更

用用户能理解的一句话说明本次改变的行为。

## 用户测什么

列最短步骤、输入和可观察预期；无需手测时说明原因。注明候选 SHA、风险等级对应的待审批事项与人工审批记录；P3 如实记录当前阶段，自动工作完成后注明“等待人工合并决定”，不把创建 PR 写成审查已通过或人工已批准。

## 详细变更

简述功能范围及必要的兼容性、迁移、风险和恢复办法；标明 P0～P3 等级、定级依据与对应单 PR 计划。P0 链接实施前的用户方案批准；P2 组合 PR 列出各相关小变更及独立验收项，混合内容按最高风险定级。按需链接关联 Issue / PR、子 PR 与依赖。

## 自证证据

列对应 SHA 的真实命令、环境、结果、CI 和证据链接，以及未测项、阻塞和剩余风险。补充独立审查者、功能与代码质量/安全各自结论及共享审查轮次。UI 截图链接到 PR 评论 / 附件，不提交代码分支。原有项目依法需要的署名或许可信息按项目要求保留。
