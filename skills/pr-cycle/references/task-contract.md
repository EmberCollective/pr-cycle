# 单任务工作者契约

协调者在启动每个 `CLAUDE_CODE` 实现会话时填入以下内容，并附当前技能、项目 `CLAUDE.md`、已有 `AGENTS.md` 与相关 `REVIEW.md` 的可读取路径。工作者实际读取后再开始，不假定文件链接自动展开。Vibe 启动的是另一 Claude 进程，不自动继承协调者通过 `--plugin-dir` 加载的技能；卡片应写明技能及本契约的绝对路径，或附完整必要规则。缺少读取权限时先回报，不能跳过约束。

```text
批次 ID / 稳定任务键：
看板卡片 ID / URL：
单 PR 计划正文或可读取路径（每份计划只对应一个 PR）：
目标与非目标：
变更等级（P0～P3） / 定级依据 / 混合变更最高风险：
审批要求 / 已有批准者、对应方案或 SHA、证据（P0 实现前须用户批准方案）：
P2 组合变更清单及逐项验收（适用时）：
可观察验收项：
仓库 / 目标分支 / 固定 base SHA：
本任务工作区 / 分支（启动后核对实际值）：
依赖及已交付提交：
允许修改的边界 / 接口约定：
独占资源锁 / 独立测试环境：
当前操作授权与预算：
技能 / 工作者契约 / 项目规则的可读取绝对路径或完整内容：

独立审查者（须与统筹、开发者分离） / 功能、代码质量及安全覆盖：
本次交付截止或无进展上报条件：
回报协调者的渠道：
```

## 工作者执行边界

- 只在分配的独立 worktree 和分支实现本任务；实际 base 与契约不符、依赖缺失或共享环境冲突时先回报，不借用其他任务工作区。
- 按 [变更风险与审批等级](../SKILL.md#变更风险与审批等级) 核对计划和授权。P0 未有用户方案批准不得实现；发现范围或风险升级时回报协调者重新定级，P2 组合不能绕过 P1 审批。
- 不自行启动其他看板任务、派生子代理、扩展并发或修改其他卡片。需要额外实现或独立审查资源时向协调者回报，由其分配。
- 不启动 Ralph Loop，也不输出协调者的 `PR_CYCLE_HANDOFF` promise；只回报本任务证据。循环和批次交接由唯一协调者处理。
- 不自动合并、部署或把人工审批记为通过；外部操作依照本任务已有授权。P3 也只自动完成开发、自证、独立审查和创建 PR，随后交接人工合并决定。缺授权时先完成可在当前权限内完成的工作，回报具体待操作对象与证据。
- 实现后亲自运行验收相关路径。测试失败就修复并重跑受影响项；环境阻塞时记录真实结果与恢复条件，不把构建、mock 或静态检查写成真实服务验收。
- UI 提供实际运行截图，按项目支持的方式附到 PR；无 UI 的规则或文档变更检查范围、链接、规则和 diff，不伪造截图。
- PR 使用技能的四节模板。尚未能创建真实 PR 时回报原因和本地分支/提交，不编造 URL，也不把任务编号当作 PR。
- 审查返工使用协调者给定的轮次与稳定发现 ID；新会话和重试不重置累计轮次。证据不足的建议先说明，不为消除评论做无意义修改。
- 第三轮结束仍未通过时停止该任务自动返工并回报，保留工作区和证据，不自行进行第四轮。

## 必须回报的结果

```text
任务键 / 卡片 ID / 工作会话 ID：
单 PR 计划 / 实际变更等级与依据 / 范围是否变化：
实际 worktree / 分支 / base SHA / head SHA：
真实 PR URL（或未创建的具体原因）：
已实现行为与未完成项：
命令 → 环境 → 实际结果 → 对应 SHA：
UI 截图或 API / 数据证据链接（适用时）：
审查发现 ID → 处置 → 修复 SHA → 验证（返工时）：
独立审查者及覆盖 SHA / 人工批准证据或待审批项 / 实际合并状态：
未测试项、剩余风险与阻塞恢复条件：
仍在运行的测试服务或进程 / 资源释放情况：
建议进入的下一阶段：
```

正常退出只能表示会话结束。协调者依据以上证据决定下一阶段，不能替独立审查者给出通过结论，工作者不得自批自己的实现。合并及人工批准完成后，由协调者另派总结 AI 按 [返工总结](feedback.md) 产出复盘及规则候选，不由开发者自行更新知识库。
