# 工作者契约

启动前提供任务、批准计划和项目规则的可读取路径。工作者必须实际读取；Vibe 会话不会继承协调者的插件和对话上下文。流程规则见 [受控工作流](workflow.md)。

## 启动输入

```text
任务 ID / 批次 ID / 当前角色：
任务目标、非目标、验收条件：
计划版本 / P0～P3 等级 / 定级理由：
当前计划批准记录（所有等级必须有，规划阶段除外）：
实际使用的提示词与输入快照：
仓库 / 工作区 / 分支 / base 与候选版本：
实施子任务 ID / 依赖 / 是否发布独立子 PR（P2）：
项目 CLAUDE.md、AGENTS.md、REVIEW.md 等可读取路径：
允许修改的边界 / 当前操作授权 / 预算：
自证要求与可用命令：
已有发现、审查证据及返工记录：
阻塞时的回报渠道和恢复条件：
```

## 角色边界

| 角色 | 允许的工作 | 不允许的工作 |
| --- | --- | --- |
| 规划／主实施 | 同一会话产出计划、等级依据和子任务，批准后实施、自测和汇总 | 批准前实施、自批计划、兼任审查或自行最终合并 |
| 实施子 Agent | 在分配的独立工作区完成计划内子任务并回报提交 | 越界认领任务、共写其他工作区、兼任审查 |
| 功能性审查 | 独立只读会话核对需求、边界、质量和测试证据 | 改代码、运行实施任务或代替安全审查 |
| 安全性审查 | 另一独立只读会话检查权限、输入和数据风险 | 自己修复并批准自己的修复 |

计划批准后后台自动派发已登记的子 Agent，通过受控启动入口绑定角色和工作区；子任务完成后继续主实施、双审、返工和 PR，无需工作者等待逐阶段人工启动。实施 CLI 关闭交互审批，授权范围仍是已批准计划；规划和审查保持只读。子任务的真实依赖未完成时不能提前启动。非发布子任务完成后，主实施者将其实际提交汇入主工作分支并验证；P2 发布子任务按记录的依赖分支形成子 PR。

发现范围、任务正文或风险变化时由规划 Agent 更新计划并取得新的批准，不能用旧版本批准继续执行。主实施会话负责返工；两类审查都不能修改代码。修改后重新核对当前版本的审查证据。

规划、审查不自行启动 Ralph 或其他工作者。实施者也不得修改审批记录、数据库或绕过受控入口；此约定不代表应用对同一 OS 用户提供身份隔离。

## 输出与证据

按照本次启动提示词规定的 `PR_CYCLE_RESULT` 格式回报，不手动调用接口写入“通过”。规划结果包括计划、等级、摘要及子任务；实施和审查结果包括 `passed`、阶段摘要及详细证据。未完成、证据不足或存在阻断问题时必须报告 `passed:false`。

详细证据包含实际工作区、提交版本、已完成与未完成项、命令和运行结果、问题位置及处置、未测项与风险。实施者执行测试，审查者阅读证据；不能把构建、静态检查或模拟服务写成真实服务验收。

PR 只有在服务创建或核实后才能报告真实 URL。尚未发布时明确写“未创建”；未合并时明确写“未合并”。阶段正常退出不代表任务通过，服务还需核对绑定会话、执行结果及当前版本。

规划审查面板仅供人类审核 Agent 的计划和等级；所有等级最终在独立的最终审查面板等待候选、双审证据和 PR 审批。后台连续三轮返工未通过会暂停，须核对原因并明确恢复；暂停只停止新派发，不终止当前 Agent。人类批准和明确执行最终合并是两个动作，工作者不能替人类操作。当前真实模型、远端 PR、集成发布及合并尚未完成端到端验收，交付时保留这一限制。
